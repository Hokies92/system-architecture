# Element 01 — Space (ChatGPT experimental branch)

This branch contains an isolated, browser-based **Element 01 — Space** prototype. It does **not** replace the original ten-element architecture or modify Claude's work.

## Run
Open [index.html](./index.html) in a browser. No build or server is required.

## Implemented
- Four systems-thinking families: surroundings; possibilities; observer construction; rules and relations.
- 20 named views, each with suggested geometric structures.
- 16 geometric choices (Euclidean, analytic, affine, projective, topological, metric, graph/network, state/phase, differential, convex, information, spherical, hyperbolic, fractal, symplectic, Lorentzian).
- Element 1 fields: definition, classification, rules/parameters, and typed link.
- Dimension, extent, rotation, boundary status, designed/observed selection.
- Field-responsive SVG construction, geometry-specific rule descriptions, JSON export.

## Scientific and engineering status
**Experimental / not validated as a scientific modeling engine.**

The visualizations are illustrative, mathematically motivated SVG constructions, **not** general-purpose implementations of the named geometries. A selected label does not establish the axioms for the modeled real-world system. Network nodes and edges are example data; state trajectories are example curves. The observer mode has no empirical observations yet. Some geometries have intentionally schematic renderers; no claims of mathematical completeness or exhaustive taxonomy are made.

A proper implementation must:
1. Separate the mathematical geometry registry from systems-thinking classification mappings.
2. Define geometry-specific typed input schemas, axioms, admissibility checks, transformations, and invariants.
3. Compute geometry from user-entered coordinates, sets, edges, functions, probability models, and observations rather than example paths.
4. Maintain separate designed and observed assertions with provenance, evidence, observer, and time.
5. Verify all literature attributions against primary sources.
6. Test at least physical, organizational, and abstract state-space cases before promoting any mapping to a standard.

Review the field schema and mapping inventory for Element 1, then authorize deeper geometry-specific implementations. No changes to Elements 2–10 are proposed.
